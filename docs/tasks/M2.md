# Task: M2 prep — everything M2 needs except SAM itself

Read `CLAUDE.md` and `docs/design/viewer-3d.md` first. Branch: `feat/m2-prep` (from `main`
after PR #1).

## Why now

The Meta hackathon starts **2026-10-26** and gives us SAM 3.1 through the Meta Model API.
Until then we build every part of M2 except the segmentation model, so that on day one
of the hackathon SAM 3.1 is one class behind an existing interface and the rest (dense
geometry, projection, voting, measurement, viewer) already works on real footage.

## Goal

Real footage → dense point cloud → masks (from any segmenter) → labelled 3D points →
findings with evidence → findings shown in the 3D viewer with video ↔ map sync.

## Part 1 — M1 fixes

1. **Fragmented reconstructions.** Aegviidu splits into 5 COLMAP models (127 of 177
   frames in the largest). Evaluate, on all four runs (South Building, church, Aegviidu,
   Orono):
   - sequential matching with loop detection (vocabulary-tree retrieval);
   - larger sequential overlap;
   - the global mapper in COLMAP/pycolmap 4.
   Measure registered frames, models, points, mean reprojection error and time. Pick by
   the numbers and make it the default. Record the choice in an ADR.
2. **Camera roll** in "view through camera": the 3D view must match the frame even when
   the camera is rolled.
3. **Initial view frames the inspected object**, not the whole landscape (for example the
   point where camera view directions converge, or the densest structure). Must work for
   every run, including image sets and forward-moving video.
4. **PostGIS for real**: a test runs `CREATE EXTENSION postgis` and a spatial query against
   the compose database; CI builds our Postgres image and runs it (amd64); the image
   builds on arm64 locally.

## Part 2 — Dense geometry without CUDA

Sparse clouds (15k–100k points) are too thin for small defects. Research and implement
densification that runs on this Mac (Apple Silicon, no CUDA), with a free GPU
(Kaggle/Colab) as a fallback. Candidates: monocular depth scaled to the sparse COLMAP
points, COLMAP MVS on a free GPU, anything better.

- **Hard constraint:** code and weights licences allow commercial use. VGGT is
  non-commercial and is out. Write the licence of everything used into the ADR.
- Behind a `Densifier` interface (next to `Reconstructor`).
- Target: **≥ 1 M points on the Orono run**, without breaking the frame ↔ point tracks
  the viewer relies on (dense points get tracks from visibility checks).
- ADR with measured numbers (points, time, depth consistency error, bundle size, viewer
  load time and fps).

## Part 3 — Mask → 3D pipeline (segmenter-agnostic)

- `Segmenter` interface: frame + text prompts → masks + confidence. Implementations:
  - `ManualMasks`: loads masks from files, so projection is tested deterministically;
  - one open-vocabulary segmenter that runs locally, **development only**, licence noted;
  - `SamApiSegmenter`: stub with the exact interface for SAM 3.1 via the Meta Model API,
    filled during the hackathon. No API calls before then.
- **Projection**: masks → 3D points using poses, depth and visibility.
- **Multi-view voting**: a finding is `confirmed` when seen in ≥ 2 frames from different
  angles, otherwise `low_evidence`. Cluster labelled points into findings.
- **Measurement**: area in m² when scale is known, otherwise relative size (never m²
  without a scale source).
- **Viewer bundle v2**: new arrays + manifest keys, version bumped; viewer still opens v1.
- **Viewer**: findings as in the Viewer3D prototype — numbered markers (red critical,
  orange watch) once seen, findings list, selected finding → timecodes → jump, timeline
  ticks for the frames where a finding is visible.

## Part 4 — Test data with defects

- CC-licensed video or photo sets of corroded tanks, pipes or steel structures.
- A public corrosion / crack segmentation dataset to evaluate segmenters.
- Store in `data/` (gitignored). Sources and licences in `docs/notes/datasets.md`.
  Non-commercial or unclear licences are listed but flagged for the owner, not used.

## Acceptance

- Reconstruction ADR with a table for all four runs; Aegviidu in fewer models with more
  registered frames, or a measured explanation why not.
- Orono dense run ≥ 1 M points, opens in the viewer at 60 fps; seen-now and build-up still
  work on dense points; through-camera view matches the frame (screenshot).
- `ManualMasks` → projection → findings is covered by a deterministic test (synthetic scene
  with known answer: confirmed vs low evidence, cluster count, area).
- The local segmenter runs end to end on a real defect video or photo set; findings show
  in the viewer with markers, list and timeline ticks (screenshots).
- `SamApiSegmenter` passes the same interface test as the others (with a fake transport).
- PostGIS test passes locally and in CI.
- `make lint test` and Playwright e2e green; `docs/notes/progress.md` current; PR opened.

## Out of scope

Running SAM 3.1 (hackathon), risk ranking (LLM), coverage states, PDF report, decision
log, database storage of findings, queue.
