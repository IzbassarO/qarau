# Task: M0 + M1 — dev environment and video → point cloud → web viewer

Give this file to Claude Code (or Codex) as the first task. Read `CLAUDE.md` first.

## Goal

A phone video of a real object becomes a 3D point cloud that opens in the browser on a
black background, coloured by height, and can be rotated, panned and zoomed with the mouse.

## Part A — M0: environment

1. `infra/docker-compose.yml` with PostgreSQL 16 + PostGIS + pgvector and MinIO. Pin
   image versions (no `latest`). Health checks on both.
2. `backend/` FastAPI skeleton: `GET /health` (checks DB and MinIO), settings from `.env`
   via pydantic-settings, ruff + mypy + pytest configured in `pyproject.toml`.
3. GitHub Actions workflow: lint + tests on push and PR.
4. `Makefile` targets: `up`, `down`, `api`, `test`, `lint`.

Done when: `make up && make api` on a clean machine gives a green `/health`.

## Part B — M1: pipeline (CLI first, no queue yet)

`pipeline/` package `qarau_pipeline` with a CLI:

```bash
python -m qarau_pipeline run --video data/samples/pipe.mp4 --out data/runs/pipe-001
```

Stages, each a module with a `run(inputs, out_dir, params) -> StageResult` function:

1. **frames** — extract frames with FFmpeg at an adaptive rate (target 150–300 frames for
   a 1–2 min video); compute blur (variance of Laplacian) and exposure scores; drop the
   worst; write `frames.json`.
2. **reconstruction** — COLMAP via `pycolmap` (or the CLI): feature extraction, sequential
   matching (video), mapping. Write `sparse/`, `poses.json`, `cloud.ply`.
3. **export** — convert to LAZ (`laspy`) and, if `PotreeConverter` is installed, to a
   Potree octree; otherwise keep a downsampled `cloud_web.ply` (≤ 2M points) for the viewer.

Behind a `Reconstructor` interface with `ColmapReconstructor` as the only implementation
for now.

## Part C — M1: viewer

`web/` React + TypeScript + Vite + Three.js. Follow `docs/design/viewer-3d.md` and the
prototype `docs/design/prototypes/Viewer3D.dc.html`. For M1 build:

- Page `/viewer/:runId` loads the cloud, camera poses and point tracks from the API.
- Black background, points coloured by height (ramp in `docs/design/README.md`), point
  size adjustable, custom `ShaderMaterial`.
- Blender-like camera: orbit / pan / zoom-to-cursor, double-click to set target, reset,
  top, side, **view through the current video camera**; damped motion.
- Camera path and frustums from the real COLMAP poses; current camera highlighted.
- **Video timeline**: scrubber over the source video's timecodes; the right panel shows
  the real extracted frame for the current time.
- **Video ↔ map sync from COLMAP tracks**: points observed by the current frame are
  highlighted; "build-up" mode darkens points first observed later in the video; points
  never observed are gray. Click a point → list of timecodes that observed it → click one
  to jump the video and fly the 3D camera to that pose.
- Run info: frames used, frames dropped for blur, points, processing time.

Export from the pipeline whatever the viewer needs for this (e.g. `cameras.json` with
pose + timecode per frame, `first_seen` and per-frame visible point indices), and add it
to the stage contract in `docs/architecture.md`.

## Acceptance

- Runs end-to-end on **three real phone videos** you shot (a rusty pipe, a fence or
  railing, a small building corner). Put them in `data/samples/` (gitignored).
- Screenshot of each in the viewer added to the PR description.
- A short `docs/notes/m1-results.md`: what worked, which videos failed and why
  (shiny metal, fast motion, low texture), processing time per video on this machine.

## Out of scope for this task

Defect detection, database storage of runs, queue, auth, desktop app. Keep it simple and
working.
