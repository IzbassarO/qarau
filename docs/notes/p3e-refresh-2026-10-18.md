# P3e: refresh viewer runs (2026-10-18)

The web app still listed runs made before the parallax keyframes (P2b) and the sky mask + far
layer (P3b). Every reference video was re-run through the current pipeline and exported as a
NEW run next to the old ones. Usage: `docs/architecture.md`, "Benchmark".

## Command

```sh
cd pipeline
uv run python -m qarau_pipeline refresh --data ../data/samples --runs ../data/runs \
  --suffix 2026-10-18 --out /tmp/refresh-2026-10-18
```

- Writes `<runs>/<video>-<suffix>` per video of `benchmark_set.toml` (same ids and
  `max_frames` as the benchmark), and `summary.json` + `summary.md` to `--out` (refused if
  `--out` is inside `--runs`). Exit 1 if a video failed.
- Refuses before any work if a target name already exists. `--keep-existing` instead leaves
  such a run untouched (read only) and reports its numbers from its `run.json` and
  `web/manifest.json`; that is how the summary below was regenerated after round 1 had
  exported all five runs.
- `--only notre-dame,room` limits the set; `--timeout-s` is per video (default 1800).

Sparse only, on the CPU (M1 Pro): `run` per video in a child process (probe, frames with
HDR→SDR, parallax keyframes, COLMAP with sky mask, export with far layer). No dense stage, no
`dense_remote`, no GPU, nothing paid. Licences: pycolmap/COLMAP (BSD-3-Clause), OpenCV
(Apache-2.0), NumPy (BSD-3-Clause), FFmpeg as an external binary; no new library, VGGT not used.

## Viewing the runs

The runs live in `data/runs`, so the viewer must serve that directory:
`cd web && QARAU_RUNS_DIR=../data/runs pnpm exec vite` (or the API with its default
`QARAU_RUNS_DIR=../data/runs`), then `/viewer/notre-dame-2026-10-18`. A viewer pointed at a
benchmark output (`QARAU_RUNS_DIR=<bench out>`, which only holds `notre-dame/`, `room/`, ...)
shows "manifest.json not found" for these names. Checked through the backend API (no server):
`GET /api/runs` lists all 5 new runs; for each, the manifest and every file it references
return 200, and `points.position.f32` / `far.position.f32` hold exactly `points` / `far.count`
× 12 bytes (notre-dame 514752 B = 42896 points, room 313248 B = 26104 points).

## Old runs untouched

Before the refresh and after it, every entry under `data/runs` was listed with its type, size,
mtime and SHA-256 (symlinks: their target), without following symlinks. All 6095 old entries
were identical afterwards; the only additions were the five `*-2026-10-18` directories. The
temp dirs (`data/runs/.<run>.*`) were renamed into place, so none was left. `GET /api/runs`
lists 22 runs: the 5 new ones next to the 17 old ones. The `--keep-existing` re-run that wrote
the summary left `data/runs` byte-identical (same listing before and after, all mtimes equal).
